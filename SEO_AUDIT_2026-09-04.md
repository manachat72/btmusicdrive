# SEO Audit — BT Music Drive

**Project:** `C:\Users\may\programpython\btmusicdrive`  
**Live domain checked:** `https://btmusicdrive.com`  
**Scope:** source/configuration, crawl/indexation, metadata, structured data, sitemap/robots, redirects, product data, and live HTTP verification.  
**Not measured in this audit:** field Core Web Vitals (CrUX), Google Search Console coverage/performance, backlink profile, and keyword rankings.

## Executive summary

The technical SEO baseline is strong: the project has an automated SEO test suite, clean canonical-domain redirects, robots.txt, a generated sitemap, noindex handling for account/transaction pages, and bot-rendered product pages with valid Product + BreadcrumbList JSON-LD.

The primary remaining opportunities are **more reliable category-page rendering for crawlers**, **richer crawlable product content**, and **completing thin product data**.

## Verified strengths

- `npm test` passed: **21 public page templates, 54 products, 10 categories, and 83 sitemap URLs** were verified by `scripts/test-seo.js`.
- `robots.txt` and `sitemap.xml` are live, return HTTP 200, and `robots.txt` declares the absolute sitemap URL.
- HTTP and `www` variants redirect with permanent redirects to `https://btmusicdrive.com/`.
- Legacy product URL `usb-flash-drive-mp3-sunarathip` permanently redirects to its canonical product URL.
- Product URLs return server-rendered metadata to Googlebot. A live Googlebot request for `/product/usb-mp3-sek-loso` returned a product-specific title and canonical URL, plus two valid JSON-LD blocks: `Product` and `BreadcrumbList`.
- The sitemap generator includes active products, categories, store pages, and blog pages; it deliberately omits fake build-date `<lastmod>` values.
- Private/customer-specific routes use `noindex, nofollow` and are excluded from the sitemap.
- Home page has preloaded LCP hero images, explicit image dimensions, lazy loading for below-fold product images, and CSS provisions intended to reduce layout shift.
- The site publishes organization, website/search-action, FAQ, blog article, product, item-list, and breadcrumb structured data across relevant templates.

## Prioritized findings

| Priority | Finding | Evidence | Recommended remediation |
|---|---|---|---|
| High | Category pages depend on client-side JavaScript to replace the generic title, description, canonical URL, Open Graph data, H1, and breadcrumbs. | `category.html` starts with generic category metadata, then changes it using JavaScript after the category slug is resolved. Vercel has no bot-specific/SSR category route. | Pre-render one static HTML page per category or add server rendering for `/category/:slug`. The initial HTML should contain final title, description, canonical, H1, breadcrumb JSON-LD, and category ItemList. |
| High | Search bots receive a very thin product page rather than the customer-facing product content. | `server/src/lib/socialOg.ts` returns only `<h1>`, one description paragraph, and one link for crawler requests. | Keep product-specific metadata server-side, but also render substantive product content: product description, specifications, shipping/returns summary, category link, and tracklist where available. This reduces rendering dependence and strengthens product-page relevance. |
| Medium | One active product has a weak/short description; two products have no tracklist data. | `products.json` audit: `tiny-but-mighty-otg-adapters` has a description under 80 characters; it and `usb-mp3-phuea-chiwit-2` have no `tracklist`. | Add a unique 150–300-word Thai description for the adapter (compatibility, use cases, limitations, warranty). Add tracklists where the product is music content; if a tracklist is not applicable, render product-specific specifications instead of an empty music section. |
| Medium | Product schema is robust for Googlebot but relies on bot-user-agent routing. | Product routing in `vercel.json` sends selected crawler UAs to the server renderer; normal requests use `product.html` and JavaScript. | Prefer a common rendered HTML source for all product requests, or at minimum test the server renderer in CI for Googlebot, Bingbot, and a generic non-JS fetcher. Avoid a long-term divergence between bot and user HTML. |
| Medium | No keyword/ranking coverage is available in the repository. | No Search Console export, keyword map, target-query metadata, or rank-tracking data was available. | Create a keyword-to-URL map for commercial and informational intent, then connect Google Search Console. Review queries, impressions, CTR, and indexed URLs monthly. |
| Low | No `hreflang` annotations exist. | Checked 29 public root/blog pages: 0 hreflang annotations. | No action needed if the storefront is Thai-only. Add `hreflang="th-TH"` and a self-referencing alternate only if regional/language variants are launched; do not add it merely as an SEO tactic. |
| Low | Performance safeguards are present, but real Core Web Vitals are not confirmed. | Source uses hero-image preload, lazy loading, image dimensions, cache headers, and delayed home bundle loading. | Run PageSpeed Insights / Chrome UX Report and fix based on real LCP, INP, and CLS data. Do not add third-party trackers/widgets without measuring the impact. |

## Implementation order

1. **Make `/category/:slug` crawlable without JavaScript** — pre-render or SSR each category page.
2. **Expand server-rendered product body content** while keeping title/canonical/structured data synchronized.
3. **Complete missing product data** for the identified product descriptions and tracklists/specifications.
4. **Connect Google Search Console**; submit the live sitemap and monitor Coverage, Page Indexing, Merchant listings, and Rich Results.
5. **Run PageSpeed Insights** for the homepage, `/shop`, a category, a product, and a blog article on mobile.
6. Build a content plan around proven Thai search intent, using blog guides to link contextually to the relevant category/product pages.
